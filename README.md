# StudySheet · 学习记录

记录每天「大科目 → 事项」的学习时长，暂停时选原因，结束后自动扣除暂停时间，
之后按周分析、帮助提升学习效率。

## 使用场景

共用一台设备（家里平板 / 一台手机），多人轮流记录。**不需要账号登录**，
点一下人名即切换身份；人名只是分组标签，不是权限边界 —— 任何拿到这台设备的人
都能看到全部记录。

数据全部存在本机浏览器 IndexedDB 里，不上传服务器。

## 技术栈

| 层 | 选型 | 原因 |
| --- | --- | --- |
| 构建 | Vite + React 19 + TypeScript | 手机浏览器直接访问，改动即时生效 |
| 样式 | Tailwind v4 | 移动端表单密集， utility 写起来快 |
| 存储 | Dexie（IndexedDB） | 本地优先、离线可用，不需要后端即可跑通 |
| 状态 | zustand | 计时器状态跨组件共享 |
| 时间 | dayjs | 起止时间与格式化 |
| 图表 | ECharts（按需引入） | 曲线 / 堆叠柱 / 饼 / 条形一套搞定 |
| 测试 | Vitest | 统计口径必须可回归 |

「图表」页懒加载，ECharts 那 587 KB 不进首屏包，每天必开的记录页仍是 354 KB。

数据层集中在 `src/db/repo.ts`：UI 不直接调 Dexie。将来要支持**各自手机、数据汇总**
（多端同步）时，只把这一层换成后端 API（建议 Next.js + Prisma + PostgreSQL，或直接用
Supabase 省掉鉴权和部署），其余代码不动。

## 核心数据模型

```
Profile       人名，共用设备上的分组标签
Subject       大科目（语文…）
TaskType      事项（默写 / 预习…），subjectId 为 null 表示通用事项
PauseReason   暂停原因，自定义项也存进字典并按使用次数排序
StudySession  一次记录，结束时冻结 netMs / gapsMs / breaksCount
SessionSegment work / break 事件流
```

`SessionSegment` 存成事件流而不是一个 `pauseMs` 字段，是为了周报能回答
「走神平均发生在开始后第几分钟」「哪类事项暂停最多」。净时长 = Σ work 段。

## 两个实现约束

**计时不靠 setInterval 累加。** 只存时间戳，每次渲染用 `Date.now()` 反算，
所以切后台、锁屏再回来都不会丢时间。见 `src/hooks/useNow.ts`。

**日期按本地时区取。** `toISOString()` 是 UTC，UTC+8 的用户在 10-19 00:30 学习会
被错标成 10-18。见 `src/lib/time.ts` 的 `dayKey`。

## 统计口径（M2）

`src/lib/stats.ts` 是唯一口径，图表和周报都读它。三条容易算错的规则：

**净时长按自然日归属。** 23:40→00:20 这条记录，「今天」视图只算 20 分钟，
「昨天」只算 15 分钟，不是整段算给开始那天。

**补录也进图表。** 补录没有 work/break 事件流，整段 `startAt→endAt` 视为一段
学习；否则图表里看不到它，而今日列表又有，两处数字对不上。

**环比用「上期同期」。** 本周只过了 1 天时，拿它比上周完整 7 天必然显示暴跌，
所以把上期也截成同样的天数，标签写作「环比同期」。

## 周报（M3）

`src/lib/report.ts` 把指标翻译成结论，**纯确定性规则，不接大模型**：这是纯本地
应用，没有服务端也没有 API Key；更关键的是每条结论都必须能被追溯到具体数字，
否则用户没法判断它是不是在胡说。所以 `Finding` 带 `evidence: string[]`，UI 原样显示。

三类规则值得单独记：

**样本不足要自己说。** 少于 3 条记录或少于 3 天有记录时标 `reliable: false`，
UI 挂「样本偏少」。需要样本量的结论各自有门槛：漏记要 `reliable`，时段规律要
≥3 条计时记录，星期分布要 ≥3 个不同的周几有记录 —— 补录没有事件流，
所以它再多也不会触发时段结论。

**星期对比必须先归一。** `weekdayMinutes` 是跨周求和的量，本月有 5 个周六、
4 个周三时，直接比总量比的是「这个月有几天」而不是「哪天更能学」。所以按
`weekdayCounts` 折成平均每个周几，且只数窗口内已过去的天。

**好消息和坏消息不互斥。** 「连续记录 3 天」和「一个月只记了 3 天」得同时说；
写成 `else if` 就只剩下好听的那条。

**不足 1 分钟不等于没记录。** 时长存的是毫秒、显示四舍五入到分钟，一条 24 秒的
记录 `totalMinutes` 是 0。这时说「这个时段还没有记录」是假话，改成「不到 1 分钟」；
也不能据此报「环比减少 100%」—— 那是四舍五入造出来的，所以趋势要求本期和上期
都 ≥30 分钟。

建议最多 3 条 —— 再多不会执行。人员对比模式下不出报告，几个人的数据混在一起
说「你偏科」是错的。

## 阶段

- [x] **M1** 人员切换、科目/事项字典、计时器（开始 / 暂停选原因 / 继续 / 结束备注）、
      补录、今日列表
- [x] **M2** 今天 / 本周 / 本月 / 全部四个窗口；全部 / 单人 / 人员对比三种范围；
      每日堆叠柱、按科目曲线、按事项曲线、科目占比、暂停原因条形、
      暂停时机分布、最长专注、计划达成率、环比同期
- [x] **M3** 周报：趋势、连续与漏记、暂停密度与时机、时段与星期分布、偏科、
      计划达成、补录可信度，每条结论附证据数字 + 最多 3 条改进建议
- [ ] **M4** 导出 CSV / JSON
- [ ] **M5** 拍照 OCR：识别作业清单生成待办，OCR 结果一律先进「草稿 + 确认」再入库
- [ ] **M6** 多端同步（此时才引入后端与邀请码，替代裸人名）
